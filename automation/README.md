# אוטומציית גילוי גמ"חים 🛰️

תשתית אוטומציה שמאתרת גמ"חים חדשים ברשת, משווה אותם לכל מה שכבר קיים אצלנו
(Strapi + הרשימה הסטטית + זיכרון ייבוא), ומייבאת רק את החדשים כ**טיוטות** —
שלא מופיעות באתר עד שאדמין מאשר אותן במסך **/admin/discovery**.

**רצה לבד לגמרי.** מקור ברירת המחדל (DuckDuckGo) מוגש בבקשת HTTP רגילה:
בלי דפדפן, בלי CAPTCHA ובלי שום התערבות אנושית. מקורות Google קיימים כ-opt-in
(`--sources=google-search`) אבל דורשים דפדפן ונחסמים באימות — לכן הם לא ברירת המחדל.

## ארכיטקטורה (OOP, בנויה להרחבה)

```
QueryPlanner ──► DiscoverySource*  ──► CandidateNormalizer ──► Deduper ──► StrapiGateway
 (סבב שאילתות)     (DuckDuckGo / Google)  (שם/עיר/טלפון/קטגוריה)  (טביעות אצבע)  (ייבוא טיוטות)
                        │                                            │
                        └────────────── StateStore ◄─────────────────┘
                              (Postgres או קובץ: ריצות, מועמדים, זיכרון כפילויות, cursor)
```

- **DiscoverySource** — מחלקת בסיס; כל מקור חדש (מדריך גמ"חים, אתר עירוני...) הוא
  מחלקה יורשת אחת ב-`src/sources/` בלי לגעת בשאר הקוד.
- **StateStore** — חוזה אחסון עם שני מימושים: `PostgresStateStore` (מועדף, `DATABASE_URL`)
  ו-`FileStateStore` (קובץ JSON ב-`automation/state/` — לפיתוח בלי DB).
- **Deduper** — טביעות אצבע: `phone:` (9 ספרות אחרונות), `name+city:` מנורמל, `url:`.
  התאמה אחת = כפילות. האינדקס נבנה מכל הסטטוסים — כולל טיוטות ונדחים, כך שגם
  גמ"ח שנדחה לא ייובא שוב.
- **סבב שאילתות מתגלגל** — מרחב השאילתות (קטגוריות × ערים) גדול מריצה אחת; כל ריצה
  ממשיכה מהמקום שבו הקודמת עצרה (cursor ב-StateStore), כך שהכיסוי מצטבר.

## התקנה (פעם אחת)

```powershell
cd automation
npm install
npx playwright install chromium   # רק אם תשתמשו במקורות Google או ב---enrich
```

## משתני סביבה

נקראים אוטומטית מ-`../.env` (של `vercel env pull`) או מ-`automation/.env`:

| משתנה | חובה? | תפקיד |
|---|---|---|
| `STRAPI_TOKEN` | לכתיבה בלבד | ייבוא טיוטות ועדכון משימות (קריאות עובדות בלי) |
| `DATABASE_URL` | מומלץ | Postgres לאחסון התפעולי (Neon/Supabase/Railway). בלעדיו — קובץ מקומי |
| `DISCOVERY_LOG_LEVEL` | לא | `debug` לפירוט מלא |

הקמת Postgres בחינם: פרויקט ב-[Neon](https://neon.tech) / Supabase → העתקת
ה-connection string ל-`DATABASE_URL` → `npm run migrate`.

## פקודות

```powershell
npm run scan          # ריצה יבשה: מאתר, משווה ומדפיס — בלי לכתוב כלום
npm run scan:apply    # ריצה אמיתית: מייבא חדשים כטיוטות ל-Strapi
npm run worker        # לולאת עובד: מבצע משימות שהאדמין יוצר בפאנל
npm run migrate       # הכנת סכמת האחסון
npm run status        # סיכום: ריצות, זיכרון, החלטות
npm run selftest      # בדיקות לוגיקה מקומיות (בלי רשת)
```

דגלים שימושיים ל-scan: `--queries=40` (היקף), `--imports=20` (תקרת ייבוא),
`--cities=ירושלים,צפת`, `--categories=medical,baby`, `--sources=google-search`,
`--enrich` (ביקור בעמוד המועמד לחילוץ טלפון), `--headful` (דפדפן גלוי).

## הזרימה המלאה

1. אדמין לוחץ **"הפעל סריקה"** ב-`/admin/discovery` → נוצרת משימה בתור
   (item בקטגוריה `__ng_discovery_job`, סטטוס `queued`).
2. ה-**worker** (רץ אצלכם: `npm run worker`) תופס את המשימה, מריץ את הצינור,
   ומעדכן התקדמות וסטטוס (`running` → `done`/`failed`). אפשר לבטל מהפאנל —
   הצינור בודק ביטול בין שאילתות ונעצר.
3. כל גמ"ח חדש נוצר כ**טיוטה** — לא מופיע באתר (הפילטר הציבורי מציג רק
   `status1='active'`), כן מופיע במסך /admin/discovery.
4. אדמין מאשר (→ `active`, עולה מיד לאתר ונעלם מהטיוטות), דוחה (→ `rejected`,
   נשאר בזיכרון כדי שלא ייובא שוב) או עורך לפני אישור.

## הרצה בענן (GitHub Actions) — ללא תלות במחשב

הקובץ `.github/workflows/discovery-scan.yml` מריץ את הסריקה על שרתי GitHub
(המאגר ציבורי ולכן דקות ההרצה חינם):

- **כל 6 שעות** — סריקה יזומה, בלי שאף אחד לוחץ.
- **בכל ריצה** — מבוצעות גם משימות שאדמין יצר בפאנל, כך שהכפתור עובד
  גם כשכל המחשבים כבויים.
- **הרצה ידנית** — לשונית Actions ← הסריקה ← Run workflow.

הפעלה חד-פעמית: הוסיפו את הסוד `STRAPI_TOKEN` תחת
Settings → Secrets and variables → Actions. **מומלץ טוקן ייעודי** ולא הטוקן
המשותף לכל האתרים, כדי שאפשר יהיה לבטל אותו בנפרד בלי לפגוע בשאר.

המצב (cursor + טביעות) נשמר בפריט Strapi יחיד (`__ng_discovery_state`),
כי runner מתחיל כל ריצה ממכונה נקייה. גם העובד המקומי משתמש באותו מצב,
כדי ששתי הסביבות לא יסרקו את אותן שאילתות.

## הערות תפעול

- **מקורות**: `duckduckgo` (ברירת מחדל, fetch בלבד) · `google-search`/`google-local`
  (opt-in, דורשים Playwright ועלולים להיחסם ב-CAPTCHA). מקור חדש = מחלקה יורשת
  אחת ב-`src/sources/` — הצינור לא צריך לדעת עליו דבר.
- **בלי דפדפן כברירת מחדל**: Chromium עולה רק אם נבחר מקור מבוסס-דפדפן או
  `--enrich`. ריצה רגילה לא פותחת דפדפן כלל.
- **קצב מנומס**: השהיה אקראית של 4–9 שניות בין שאילתות ותקרת שאילתות לריצה.
- **אם מקור נחסם**: הריצה מסתיימת עם `blocked`, הפאנל מציג אזהרה כתומה,
  וה-cursor **לא** מתקדם — כך שהשאילתות שלא רצו יחזרו בסריקה הבאה.
- **מיקום/קואורדינטות**: טיוטות מיובאות בלי lat/lng בכוונה (לא מעמיסים על
  Nominatim בזמן הסריקה). אחרי אישור, מסך "השלמת מפה" בפאנל משלים אותן באצוות.
- **סקייל**: כמה workers יכולים לרוץ במקביל (תפיסת משימה בודקת שהסטטוס עדיין
  `queued`), וה-cursor המשותף ב-Postgres מונע חפיפת שאילתות בין ריצות.
- הרצת כתיבות לפרודקשן נעשית על-ידכם (PowerShell עם `.env`), בהתאם לנוהג הקיים
  של סקריפטי התחזוקה.
